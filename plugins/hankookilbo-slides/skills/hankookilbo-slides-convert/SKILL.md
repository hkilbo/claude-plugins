# 기존 문서 서식 변환

외부에서 받은 덱이나 개인이 만든 자료를 한국일보 공식 서식으로 옮긴다. **서식만 바꾸는 것이 아니라 구조를 사내 보고 형식으로 재편하는 작업이다.**

`hankookilbo-slides` 스킬의 규격과 `assets/` 자산을 함께 사용한다. 그 스킬의 SKILL.md 를 먼저 읽는다.

## 0단계: 표지 유형 확인

요청문에 "표지 A · 연녹" 또는 "표지 B · 아트워크" 같은 단서가 있으면 그대로 쓰고 묻지 않는다. 없으면 원본 표지 성격에 맞춰 정하되, 판단이 어려우면 **표지 A** 를 쓴다. 질문 도구가 응답을 받지 못하면 재시도하지 않고 표지 A 로 진행한 뒤 완성 후 알린다.

## 1단계: 원본을 읽는다

```bash
markitdown <원본>.pptx
# pptx 스킬이 있으면 썸네일 그리드도 만든다
python3 "$(find ~ /var/folders /tmp -path '*skills/pptx/scripts/thumbnail.py' 2>/dev/null | head -1)" <원본>.pptx <원본이름>-thumbs
```

텍스트와 썸네일을 모두 확인한다. 썸네일 없이 텍스트만 보면 원본의 시각 구조를 놓친다.

## 2단계: 내용을 장표 유형에 다시 배정한다

원본의 슬라이드 순서를 그대로 옮기지 않는다. 내용을 뜯어서 사내 보고 구조에 재배치한다.

| 원본에 이런 내용이 있으면 | 이렇게 옮긴다 |
|---|---|
| 표지 | 표지 A 또는 B — **사용자에게 유형을 묻는다** |
| 아젠다 · 목차 | CONTENTS 장표 |
| 섹션 구분 슬라이드 | 장 구분 간지 (`Ⅰ. Ⅱ. Ⅲ.` 로마숫자 부여) |
| 불릿 3~4개 나열 | 3열 표 또는 2×2 박스 그리드 |
| 큰 숫자 카드 | 표 또는 박스 그리드 (수치 자리표 형식 준수) |
| 인용 · 한 줄 강조 | `GREEN_PALE` 강조 박스 |
| 비교 · 전후 대조 | 표의 두 열로 (좌 도입 전 / 우 도입 후) |
| 로드맵 · 타임라인 | 실행과제 표 (단계 · 과제 · 활동 · 기간) |
| 결론 · 제안 | `GREEN_DEEP` 강조 배너 + 지표 표 |

**장표 제목은 사내 형식으로 다시 쓴다.** `번호. 대분류 _ ① 소제목` 형태다. 예: `3. Code Connect 개요 _ ① 정의와 산출물`.

## 3단계: 원본에서 버릴 것

- 원본 색상 · 폰트 전부. 공식 토큰으로 교체한다.
- 그라디언트 · 그림자 · 둥근 모서리 · 아이콘 장식.
- 다크 배경 슬라이드. 본문은 항상 흰 배경이다.
- 원본 로고 · 워터마크.
- 16:9 비율. A4 가로 `11.7″ × 8.27″` 로 바꾼다.

## 4단계: 변환하고 대조한다

`hankookilbo-slides` 의 4단계 방식으로 생성한다. **`assets/example-build.js` 를 복사해 쓰고, 자산 경로 확인(0단계)을 먼저 통과한다.** 완료 후 **원본과 새 문서의 내용을 대조한다.**

```bash
markitdown <원본>.pptx > /tmp/before.txt
markitdown <결과>.pptx > /tmp/after.txt
```

누락된 수치 · 고유명사 · 출처가 없는지 확인한다. 서식 변환에서 내용이 사라지는 것이 가장 심각한 결함이다.

이어서 서식 점검기를 돌린다.

```bash
python3 "<hankookilbo-slides 스킬 경로>/assets/verify.py" <결과>.pptx
```

위반이 남아 있으면 고치고 다시 돌린다.

## 5단계: 보고한다

사용자에게 다음을 알린다.

- 원본 N장 → 결과 M장 (장수가 바뀐 이유)
- 어떤 내용을 어떤 장표 유형으로 옮겼는지
- **의도적으로 뺀 내용**과 그 이유
- 원본에 수치나 출처가 불명확해 확인이 필요한 항목

원본에 근거가 없는 내용을 채워 넣지 않는다. 빈 칸은 빈 칸으로 두고 사용자에게 묻는다.
