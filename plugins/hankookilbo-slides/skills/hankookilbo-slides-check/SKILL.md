# 서식 준수 점검

pptx 가 한국일보 공식 서식을 지켰는지 기계적으로 확인하고, 어긋난 항목을 위치와 함께 보고한다. **점검만 한다. 사용자가 요청하지 않으면 고치지 않는다.**

기준은 `hankookilbo-slides` 스킬의 규격이다. 그 SKILL.md 를 먼저 읽는다.

## 1단계: 자동 점검기를 돌린다

`hankookilbo-slides` 스킬의 `assets/verify.py` 가 캔버스 · 폰트 · 팔레트 · 로고 · 제목 위치 · 구분선 · placeholder 를 한 번에 점검한다. 외부 의존이 없어 어느 환경에서든 돌아간다.

```bash
python3 "<hankookilbo-slides 스킬 경로>/assets/verify.py" <대상>.pptx
```

경로를 모르면 찾는다.

```bash
find ~ /var/folders /tmp -name verify.py -path "*hankookilbo*" 2>/dev/null | head -1
```

출력이 위반 · 주의 · 참고로 분류되어 나온다. 이 결과를 4단계 보고의 기준으로 삼는다.

## 2단계: 자동 점검이 못 잡는 것을 XML 에서 본다

필요하면 직접 뜯어 확인한다.

```bash
python3 -c "import sys,zipfile; zipfile.ZipFile(sys.argv[1]).extractall('u')" <대상>.pptx
```

- **표 헤더 채움** — 헤더 행의 `srgbClr` 이 `14362D` 또는 `215732` 인지, 글자가 흰색 Bold 인지
- **표지 유형** — 연녹 면(`EEF8E0`) 사각형이 `x 2.34″` 에 있으면 A, `cover-b-artwork` 이미지가 하단에 있으면 B. 둘 다 아니면 자체 제작이므로 위반
- **간지** — 제목 외 요소가 있는지
- **레이아웃 반복** — 같은 구조가 3회 이상 연속되는지

## 3단계: 시각 점검

```bash
soffice --headless --convert-to pdf <대상>.pptx
pdftoppm -jpeg -r 100 <대상>.pdf slide
```

`pptx` 스킬이 있으면 `scripts/office/soffice.py` 를 쓴다. **렌더 이미지를 실제로 열어서** 확인한다. 아래는 XML 로 잡히지 않는다.

- 텍스트가 상자나 슬라이드 경계를 넘침
- 표와 아래 요소가 겹침 (가장 흔함)
- 본문 슬라이드가 흰 배경이 아님
- 그라디언트 · 그림자 · 둥근 모서리 강조

렌더 도구가 없으면 **시각 점검을 못 했다는 사실을 보고에 명시한다.**

## 4단계: 보고

표로 정리한다. 심각도를 구분한다.

| 심각도 | 기준 |
|---|---|
| **위반** | 캔버스 크기 · 폰트 · 팔레트 외 색상 · 로고 누락 · placeholder 잔존 · 텍스트 넘침 |
| **주의** | 위치 편차 0.1″ 이상 · 빨강 남용 · 같은 레이아웃 3회 이상 반복 |
| **참고** | 여백 불균형 · 표 열 정렬 불일치 |

각 항목에 **슬라이드 번호 · 발견된 값 · 기대값 · 수정 방법**을 적는다.

```
| 슬라이드 | 심각도 | 항목 | 발견된 값 | 기대값 |
|---|---|---|---|---|
| 전체 | 위반 | 캔버스 크기 | 13.33″ × 7.5″ (16:9) | 11.7″ × 8.27″ (A4 가로) |
| 4 | 위반 | 표 헤더 색 | 4472C4 | 14362D |
| 7 | 주의 | 제목 위치 | y 0.32″ | y 0.14″ |
```

위반이 없으면 그렇게 보고한다. 없는 문제를 만들어내지 않는다.

마지막에 사용자에게 수정 여부를 묻는다. 수정을 맡으면 `hankookilbo-slides-convert` 로 넘어간다.
