# 한국일보 인터랙티브 페이지 제작 스킬

이 스킬은 한국일보 인터랙티브 페이지를 만드는 담당자(사내 제작자 또는 외주 제작사)가
기획부터 전달용 zip까지 클로드코드만으로 끝낼 수 있게 하기 위한 것입니다.

## 핵심 원칙 (가장 중요)

- **프로젝트는 `index.html` 하나입니다.** 여기에 공유 이미지 2장(`share.jpg`, `share_kakao.jpg`)과 본문에 쓰는
  이미지·영상이 붙습니다. 설치도 빌드도 없고, 만든 폴더를 그대로 올립니다.
- **기술/구조의 단일 진실 공급원은 `references/`(규칙)와 `assets/template/index.html`(코드)입니다.**
  템플릿은 이 파일 하나입니다. 프로젝트 폴더에 복사한 뒤 그 파일을 고칩니다. 고칠 곳 다섯 군데와
  고치지 않는 곳(`hk-common-css`·`hk-common-js` 블록)은 `references/template-overview.md`에 있습니다. 규칙과 설명은 `references/`에 작업 상황별로
  나뉘어 있으니 **그 상황에 필요한 파일 하나만** 읽으세요(아래 "참고 파일").
  이 스킬의 다른 어떤 설명보다 이 문서들이 우선합니다.
- **기획 인터뷰(1단계)에서 만드는 브리프(`brief.md`)는 "최초 기획 메모"일 뿐, 이후
  절대 바꿀 수 없는 규칙 문서가 아닙니다.** 제작 도중 사용자가 다른 지시를 내리면
  항상 **최신 지시가 우선**합니다.
- 반대로 아래는 몇 번을 뒤엎는 지시가 오더라도 항상 지켜야 하는 **고정 규칙**
  입니다 (세부 내용은 `references/template-overview.md` 「필수 요건」과 「규칙과 함정」):
  1. `references/template-overview.md` 「필수 요건」에 있는 모든 항목
     (GA4 `G-HR08PM6YWZ` 하나/카카오SDK v2/한국일보 통계 `hkAnalTag_hub.js`, 인터랙티브 임베드, 바이라인,
     `.body-wrapper` 구조, 공통 블록 두 개 등) — 절대 생략·삭제·ID변경 금지
  2. 스크롤 컨테이너는 `.body-wrapper` 하나(`window.scrollY`, `window.addEventListener("scroll")`은 동작하지 않음).
     페이지 배경(`--bg-base`)은 단색만
  3. 올리는 파일 전체 용량 상한 (권장 10MB / 스킬 상한 80MB)
  4. 폰트는 한국일보 CDN(`https://assets.hankookilbo.com/fonts/hk_fonts.css`)의 2종만 사용 —
     `var(--font-base)`(`'Pretendard Variable'`, 가변 45~920) / `var(--font-serif)`(`'NanumMyeongjo'`, 400/700/800).
     폰트 파일을 프로젝트에 두거나 `@font-face`를 직접 선언하지 않는다(`self_check.js` 실패). 다른 서체가 필요하면
     한국일보 프론트개발팀에 `hk_fonts.css` 추가를 요청한다 (`references/theming.md`)
  5. 사진·영상 등 모든 소재는 사용 권한이 확인된 것만 쓰고, 화면에 출처(크레딧)를 표기
  6. 공유 이미지 2장 필수 — `index.html` 옆에 `share.jpg` **1200×630**(페이스북·X),
     `share_kakao.jpg` **800×800**(카카오톡), 둘 다 JPG. `self_check.js`가 파일 존재와
     픽셀 크기를 검사하며, 없거나 크기가 다르면 올리지 않는다
- 이 두 층(브리프=유동적, 고정 규칙=불변)을 헷갈리지 않는 것이 핵심입니다.
  판단 기준: **"이걸 지키지 않으면 올릴 수 없는가?"** 라면 고정 규칙,
  아니면 브리프입니다.
- 디자인 방향은 `frontend-design` 스킬(이 플러그인과 함께 설치됨)로 정합니다(1단계 끝
  「디자인 방향 정하기」). 지시가 부딪히면 **고정 규칙 > 브리프 > `frontend-design`** 순서로 따릅니다.
  예: `frontend-design`이 다른 서체를 권해도 폰트는 CDN 2종만 씁니다.

## 1단계 — 기획 인터뷰

사용자가 이미 답을 준 항목은 다시 묻지 말고, 빠진 것만 물어보세요.

1. 기획 배경, 기획 목적
2. 대상 소재(사진·영상·데이터) 설명, 원하는 스토리
3. 원하는 연출 방식 — 정해진 틀은 없습니다. 담당자 말로 "읽는 사람이 어떻게 보게 할까요?"라고 묻고,
   잘 모르면 기사 성격에 맞춰 추천합니다. 예: 스크롤로 이어지는 여정형, 예전/지금 비교 슬라이더, 시간순 타임라인,
   지도 위 이동 경로, 풀스크린 갤러리, 버튼으로 화면을 넘기는 한 화면 페이지(퀴즈·선택지·미니게임).
   이 답으로 정해지는 건 둘뿐입니다 — **페이지가 스크롤되는지**(4번에서 추천할 값, `references/structure.md`)와
   필요한 라이브러리(`hankookilbo-interactives-libs` 스킬). 라이브러리는 화이트리스트 없이 자유롭게 고르되
   활발히 유지보수되는 것을 우선하고, 설치 없이 CDN에서 불러옵니다.
4. **크레딧 위치** — 항상 묻습니다. 담당자 말로:
   "페이지 끝에 제작진 이름과 '다른 인터랙티브 기사' 추천 카드가 함께 나옵니다. **맨 아래까지 내렸을 때**
   보여 줄까요, 아니면 **특정 화면에 도착했을 때**(예: 끝에 있는 퀴즈를 다 푼 뒤) 보여 줄까요?"
   → 맨 아래 = `index.html` 첫머리 `<html>` 태그의 `data-credits="bottom"` / 특정 화면 = `data-credits="end"`.
   추천값을 함께 말합니다: 스크롤로 읽는 페이지면 `bottom`, 버튼으로 화면을 넘기는 페이지면 `end`
   (`bottom`은 바이라인이 본문 뒤에 붙어 스크롤 없는 페이지에 스크롤이 생기고 그 스크롤에 GNB가 숨습니다
   — 스크롤 없는 페이지는 `end`. `references/common-area.md`).
5. 제목, 요약 설명(80자 이내 권장) — 브라우저 탭 제목, 공유 카드 제목·설명, 바이라인 제목에 들어갑니다.
6. 폴더명(영문 소문자+하이픈/언더스코어) — 페이지 주소 `https://www.hankookilbo.com/interactive/<폴더명>/`이 됩니다.
7. 연결 기사 키("A"+숫자 19자리) — **한국일보 기획팀이 발행**하는 값입니다.
   담당자가 직접 만들 수 없으니, 한국일보 담당자를 통해 발급받아 달라고 안내하세요.
   아직 못 받았다면 템플릿 자리 값(`A0000000000000000000`)으로 두고 넘어가되, `brief.md`에 "기사키 미발급
   — 올리기 전 한국일보 확인 필요"라고 반드시 남기세요. 자리 값인 동안 `self_check.js`는 실패합니다.
   이 값은 `index.html` 세 곳에 똑같이 들어갑니다 — 통계 메타 `hk:nw_newsid`, `hk:nw_pagecode`(`hk_news_read_` 뒤),
   **인터랙티브 임베드 스크립트의 `?Nid=`**(헤더 + 하단 추천 카드, `references/common-area.md`). `Nid`는 대문자 N입니다.
   자리 값인 채 올리면 추천 카드에 자기 기사가 뜨거나 카드가 안 뜹니다.
8. 게시 예정일 — 바이라인의 `Posted by` 날짜
9. 제작진 — 바이라인에 역할별로: 취재/사진/영상/인터랙티브 기획제작 등
10. 소재 파일(사진·영상·데이터) 첨부 + 각 소재의 출처(크레딧)와 사용 권한 확인
11. **공유 이미지 2장** (크기·파일명은 고정 규칙 6) — 담당자에게 "링크를 공유했을 때 카드에 뜰 이미지 두 장"이라고
    설명하고 받으세요. 없으면 대표 사진으로 두 크기를 만들어 보여 주고 승인받습니다.
12. 디자인 컨셉, 톤&무드. 라이트/다크는 따로 묻지 않습니다. 헤더 아이콘 색은 템플릿이 페이지 배경색을 보고
    자동으로 맞춥니다 (`references/theming.md`).
13. 레퍼런스 사이트
14. 하지 말아야 할 것 (제약사항)

4~9번 값이 `index.html`의 어디에 들어가는지는 `references/template-overview.md` 「`index.html`에서 고칠 곳」 표에 있습니다.

**콘텐츠 브리프 형식**: 사진·문구·배치를 담당자가 아래 형식으로 전달하면
왔다갔다하는 질문 없이 바로 본문(`index.html`의 `<main>`)에 옮길 수 있습니다. 담당자에게 이 형식을
안내하세요:

```
챕터 1: [제목]
- 본문: (문단1) / (문단2)
- 사진: [파일 경로 또는 링크] — 배치: 본문 사진 / 갤러리만 / 둘 다
- 크레딧: (출처·저작권 표기. 공통값과 다르면 명시)

챕터 2: ...
```

소재 파일은 `index.html` 옆 `img/` 폴더에 저장하고 상대 경로(`img/파일명.jpg`)로 씁니다. 링크로 받은 사진은
`curl -sL -A "Mozilla/5.0" -o <파일명> "<링크>"`로 받아 같은 폴더에 넣으세요.

메인 스토리 배경(연출 방식)과 어울리지 않는 사진·챕터(예: 산악 배경인데
국내 훈련 사진처럼 톤이 다른 소재)는 억지로 메인 스크롤에 끼워 넣지 말고,
갤러리 하단에 별도 그룹으로 분리하는 것도 좋은 패턴입니다 — 실제 사진이
아직 없으면 그룹 제목과 안내 문구만 먼저 넣고 "사진 준비 중"으로 표시하세요.

답변을 모으면 프로젝트 폴더에 `brief.md`를 작성하세요. **주의**: `brief.md`는
`index.html`을 대체하지 않습니다 — 제목/주소/바이라인/크레딧 위치 같은 값은
`index.html`에만 씁니다. `brief.md`에는 거기에 없는 것(기획 배경, 연출 방식,
소재 출처, 디자인 방향, 기사키 미발급 같은 특이사항)만 담습니다. `brief.md`는 올리지 않습니다.

**디자인 방향 정하기**: `brief.md`를 쓴 뒤 `frontend-design` 스킬을 불러 기사 주제와 12번 톤&무드에서
방향을 정합니다. 이때 제약으로 폰트 2종(`--font-base`·`--font-serif`), 배경색은 `--bg-base` 단색 하나, 3번에서 정한 연출 방식을 함께 넘깁니다.
결과는 `brief.md`의 「디자인 방향」에 아래 네 가지로 적고 담당자에게 한 번 보여 줍니다. **승인을 기다리지 않고 바로
2단계로 넘어갑니다** — 담당자는 브라우저에서 실제 화면을 보고 판단합니다.

- 색 4~6개(hex) — 그중 하나가 페이지 배경색(`--bg-base`, 단색)
- 글자 위계 — 제목·본문·캡션에 쓸 서체(고딕/명조)와 글자 크기 변수(`--font-18` 등)
- 모션 강도 — 차분함 / 보통 / 활발함 중 하나와 쓸 곳
- 피할 것 — 이 기사에 어울리지 않는 연출

엄숙한 기사에서 신문식 단 구성·헤어라인을 쓰려면 「디자인 방향」에 그렇게 적으세요.
`frontend-design`은 이를 흔한 AI 연출로 보고 피하지만, 브리프에 적힌 지시는 따릅니다.

## 2단계 — 제작

**시작하기 전에 `references/template-overview.md`를 읽으세요.**

1. 프로젝트 폴더(이름 = 6번 폴더명)를 만들고 `assets/template/index.html`을 복사합니다. 복사할 것은 이 파일 하나입니다.
2. 1단계에서 모은 값을 `index.html`에 직접 씁니다. 같은 값이 여러 곳에 반복되므로 `template-overview.md`
   「`index.html`에서 고칠 곳」 표대로 빠짐없이 바꿉니다 (제목, 설명, 주소, 기사 키, 게시일, 제작진, `data-credits`).
3. 공유 이미지 2장을 `index.html` 옆에, 소재를 `img/`에 넣습니다.
4. 본문을 씁니다. 기사 글은 `<main>` 안에 HTML로 직접, 스타일은 "프로젝트 스타일" `<style>`, 동작은 맨 아래
   "프로젝트 스크립트" `<script>`에 씁니다. 정해진 패턴 없이 브리프의 연출 방식과 「디자인 방향」대로 짭니다.
   지킬 규칙은 `references/structure.md`와 `references/template-overview.md` 「규칙과 함정」입니다.
   `index.html`에 안내·설명 주석을 남기지 마세요 — 파일이 그대로 게시되어 브라우저의 페이지 소스 보기에 주석이 보입니다.
   메모는 `brief.md`에 적습니다. 뻔하지 않은 프로젝트 로직을 설명하는 한 줄 코드 주석은 괜찮습니다.
5. 띄워서 보여 줍니다 (아래 "제작이 끝나면").

**공통영역(헤더·추천 카드) 배선**: 모든 페이지에 같은 규칙입니다. 헤더 아이콘 색, 내리면 GNB 숨김·올리면 바탕,
크레딧 진입은 템플릿의 `hk-common-js` 블록이 자동으로 정합니다 (`references/common-area.md`). 이 블록과
`hk-common-css` 블록은 고치지 않습니다.

| `data-credits` | 할 일 |
|---|---|
| `bottom` | 없음. 바이라인이 화면 위에서 60% 지점에 닿거나 맨 아래에 오면 크레딧(바이라인 + 추천 카드) |
| `end` | 마지막 화면에 들어갈 때 `hkCommon.showCredits(target)`, "처음부터 다시"처럼 크레딧을 떠날 때 `hkCommon.hideCredits()` (`references/structure.md`). 그 밖에는 없음 |

GNB·추천 카드를 CSS나 스크롤 코드로 직접 건드리지 마세요 — `<html data-*>`만이 통로이고, 그것도 공통 블록이 씁니다.
첫 화면과 스크롤 없는 페이지의 화면 높이는 `var(--screen-h)`(GNB 아래 한 화면)로 잡고, 콘텐츠에 GNB 높이만큼 여백을
또 주지 마세요 (`references/structure.md`).

**라이브러리 선택**: 캐러셀/슬라이더, 스크롤 인터랙션, 지도, 지도 위 데이터
시각화, 상태 공유(퀴즈·계산기)가 필요하면
`hankookilbo-interactives-libs` 스킬의 규칙표를 먼저 확인하세요. 라이브러리는 CDN에서 불러옵니다.
해당 없으면(예: 순수 스크롤형 사진 에세이) 참고할 필요 없습니다.

**소재 출처 표기**: 사진·영상마다 화면에 출처(크레딧)를 표기하세요. 사진 바로
아래 캡션에 넣는 것이 기본이고, 갤러리처럼 캡션 자리가 없으면 섹션 끝이나
바이라인 위에 출처 목록을 둡니다. 외부 링크는 모두 새 창/새 탭으로 엽니다
(`target="_blank" rel="noopener"`).

**방문자 데이터를 모아서 보여줘야 하는 기능(방명록, 참여 이벤트 등)을
요청받으면**: 이 템플릿은 정적 파일만 올리므로 자체 백엔드를 둘 수
없습니다. 구글시트 + Apps Script를 "웹앱으로 배포"해 무료 백엔드처럼
쓰는 방법을 기본으로 제안하세요 (`doGet`/`doPost`로 시트 읽기/쓰기, POST는
`Content-Type: text/plain`으로 보내면 브라우저 preflight 없이 응답을 읽을
수 있음). 실제 시트 생성과 배포는 사용자의 구글 계정이 필요해 Claude가
대신 할 수 없으니, Apps Script 코드는 만들어 주고 배포 절차는 `brief.md`에 적어 안내하세요.
연동 전에는 `localStorage` 기반 데모 모드로 동작하게 해서, 실제 연동 전에도 바로 테스트해볼 수 있게
하는 것을 권장합니다.

**제작이 끝나면 바로 띄워서 보여 줍니다.** 프로젝트 폴더에서 `python3 -m http.server 3000`을 백그라운드로 실행하고
(포트는 3000 고정 — 다른 포트면 CDN·추천 카드 API가 CORS로 막힙니다) 담당자에게 "브라우저에서 `http://localhost:3000` 을
열어 보세요"라고 안내합니다. 스크린샷 파일을 보라고 하지 않습니다. 이후 수정은 새로고침하면 보입니다.

## 3단계 — 보면서 고치기

담당자는 `localhost:3000`에서 직접 넘기며 봅니다. Claude는 **자체 검사를 자동으로 돌리고 결과만 스스로 처리**합니다.
담당자에게 파일을 열어 보라고 하지 않습니다. 빌드가 없으니 고친 뒤 바로 돌립니다.

```bash
# 프로젝트 폴더에서. <스킬폴더> = 이 SKILL.md 가 있는 폴더
node <스킬폴더>/scripts/self_check.js .
node <스킬폴더>/scripts/qa_playwright.js --entry ./index.html --out ./qa-report --sections "<챕터 선택자>"
```

`qa_playwright.js`가 쓰는 Playwright는 기기당 한 번만 설치합니다. **프로젝트 폴더 안에는 설치하지 않습니다**
(그 폴더는 그대로 올리는 폴더입니다).

```bash
npm install --prefix ~/.hk-interactives playwright
npx --prefix ~/.hk-interactives playwright install chromium
```

- `self_check.js`: 필수 스크립트·메타, **메타 일치**(주소·기사 키·제목·설명이 여러 곳에서 서로 같은지), 템플릿 자리 값이
  남았는지, 공통 블록 두 개와 `<ul class="share-tools">`가 스킬 원본과 같은지, `data-credits="end"`의 `showCredits` 호출, 배경 단색, 폰트, 용량, 공유 이미지 2장.
  **FAIL(✕)은 바로 고칩니다.** 기사키·제작진처럼 담당자 입력이 필요한 FAIL만 모아서 한 번에 묻습니다.
  공통 블록이나 공유 버튼이 원본과 다르다는 경고(!)가 나오면 템플릿에서 그 부분을 다시 복사합니다.
- `qa_playwright.js`: 실제 Chromium으로 헤더 마운트, `<html data-*>` 초기값, 첫 요소가 GNB 아래에서 시작하는지, GNB 스크롤 규칙,
  크레딧·추천 카드, 웹폰트, 콘솔 에러를 검사하고 `qa-report/`에 스크린샷을 남깁니다. ✕가 나오면 Claude가 고칩니다.
  스크린샷은 Claude가 레이아웃 문제를 찾는 용도입니다 — 담당자 확인용으로 쓰지 않습니다.
  `--sections`에는 챕터 요소 선택자(예: `".step"`, `"main > section"`). 모바일에서 고정 그림이 글을 가리면 `--anchor-mobile 0.5`.
- 담당자가 보는 3000 서버는 끄지 않습니다. `qa_playwright.js`는 3000에 이 페이지가 이미 떠 있으면 그 서버를 그대로 씁니다.
  다른 페이지가 떠 있으면 멈추므로 그 서버를 끄고 다시 돌립니다.
- 서체가 기본 서체로만 보이고 `assets.hankookilbo.com/fonts` 요청이 CORS 에러면 코드 문제가 아니라 CDN 허용 목록 문제입니다.
  "한국일보 프론트개발팀에 CloudFront CORS 허용 목록(`localhost:3000`, `www.hankookilbo.com`) 확인 요청"이라고 안내하고 넘어갑니다.

**멈추는 지점은 하나입니다.** 자체 검사가 끝나면 담당자에게 "localhost:3000에서 보고 고칠 곳을 말해 달라"고 하고 기다립니다.
봐 달라는 것은 3~5개로 구체적으로: 사진·그림이 맞는 챕터에 들어갔는지, 글이 가려지거나 잘린 곳, 색·분위기, 모바일(창을 좁혀서)에서 글자가 읽히는지.
피드백이 오면 고치고 → 새로고침해 보라고 하고 → 바뀐 곳만 알려 줍니다. 큰 수정 뒤에는 `self_check.js`만 다시 돌립니다.

## 4단계 — 전달용 zip 만들기 (담당자가 "마무리해줘"·"zip 만들어줘"라고 할 때만)

보면서 만드는 동안에는 하지 않습니다. 끝났다고 할 때 한 번에 합니다. 올리는 일은 이 스킬의 범위가 아닙니다 —
**풀어서 S3에 그대로 올리면 되는 zip**을 만드는 데까지가 끝입니다.

1. **최종 검사**: `self_check.js`를 다시 돌립니다. 모두 통과해야 합니다. 이어서 `references/template-overview.md`
   「올리기 전 확인」을 하나씩 봅니다 (스크립트가 못 보는 것: 공유 버튼 동작, 모바일 인앱 브라우저 스크롤, 오탈자 등).
2. **zip**: 프로젝트 폴더의 **바로 위 폴더에서** 만듭니다. 작업 기록(`brief.md`·`qa-report/`)은 넣지 않습니다.

   ```bash
   cd .. && zip -r <폴더명>.zip <폴더명> -x "<폴더명>/brief.md" "<폴더명>/qa-report/*" "<폴더명>/.git/*" "<폴더명>/node_modules/*" "*.DS_Store"
   ```

   zip 안에는 `<폴더명>/` 폴더 하나가 있고, 그 안에 올릴 파일만 있습니다 (`index.html`·`share.jpg`·`share_kakao.jpg`
   +본문 이미지·`data/`·따로 둔 `.css`·`.js`). 프로젝트 폴더 이름이 6번 폴더명과 같아야 주소가 맞습니다.
   만든 뒤 `unzip -l <폴더명>.zip`으로 목록을 확인합니다.
3. **안내**: zip 파일의 위치를 알려 주고 이렇게 말합니다 — "이 zip을 풀면 `<폴더명>` 폴더가 나옵니다. 그 폴더를 S3 버킷의
   `v/` 아래에 그대로 올리면 `https://www.hankookilbo.com/interactive/<폴더명>/` 에서 열립니다." 올리는 방법은
   `references/template-overview.md` 「올리기」에 있습니다.

완료 문서를 따로 쓰지 않습니다. 올리는 사람이 알아야 할 특이사항(외부 API 키, 구글시트 연동 등)은 `brief.md`에 남기고,
zip을 전달할 때 함께 말해 달라고 안내합니다.
