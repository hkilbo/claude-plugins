# 한국일보 인터랙티브 페이지 제작 스킬

이 스킬은 한국일보 인터랙티브 페이지를 만드는 담당자(사내 제작자 또는 외주 제작사)가
기획부터 전달용 zip까지 클로드코드만으로 끝낼 수 있게 하기 위한 것입니다.

## 핵심 원칙 (가장 중요)

- **기술/구조에 관한 모든 것의 단일 진실 공급원은 `references/hk-interactive-template.md`
  입니다.** 한국일보 개발부문이 만든 공식 문서이며, Astro+React 스택, 폴더 구조, `META.ts`,
  인터랙티브 헤더(임베드 스크립트)/`Byline`, GA/GTM/카카오 SDK 등 필수 스크립트, 배포 규칙이
  전부 여기 정의돼 있습니다. **2단계(제작)를 시작하기 전에 이 문서 전체를 반드시
  읽으세요.** 이 스킬의 다른 어떤 설명보다 이 문서가 우선합니다.
- **기획 인터뷰(1단계)에서 만드는 브리프(`brief.md`)는 "최초 기획 메모"일 뿐, 이후
  절대 바꿀 수 없는 규칙 문서가 아닙니다.** 제작 도중 사용자가 다른 지시를 내리면
  항상 **최신 지시가 우선**합니다.
- 반대로 아래는 몇 번을 뒤엎는 지시가 오더라도 항상 지켜야 하는 **고정 규칙**
  입니다 (세부 내용은 `references/hk-interactive-template.md`, 특히 "0-1. 필수
  요건"과 "12. 규칙과 함정" 참고):
  1. `references/hk-interactive-template.md`의 "0-1. 필수 요건"에 있는 모든 항목
     (GTM/GA/카카오SDK v2/한국일보 통계 스크립트, 인터랙티브 임베드, Byline, body-wrapper
     구조 등) — 절대 생략·삭제·ID변경 금지
  2. `npm run build` 산출물은 항상 `dist/` (astro.config.mjs의 `outDir` 변경 금지)
  3. 전체 산출물 용량 상한 (템플릿 권장 10MB / 스킬 상한 80MB)
  4. 폰트는 한국일보 CDN(`https://assets.hankookilbo.com/fonts/hk_fonts.css`)만 사용.
     `public/fonts/`, 폰트 파일 커밋, `@font-face` 직접 선언 금지
  5. 사진·영상 등 모든 소재는 사용 권한이 확인된 것만 쓰고, 화면에 출처(크레딧)를 표기
- 이 두 층(브리프=유동적, 고정 규칙=불변)을 헷갈리지 않는 것이 핵심입니다.
  판단 기준: **"이걸 지키지 않으면 배포가 불가능한가?"** 라면 고정 규칙,
  아니면 브리프입니다.

## 1단계 — 기획 인터뷰

사용자가 이미 답을 준 항목은 다시 묻지 말고, 빠진 것만 물어보세요.

1. 기획 배경, 기획 목적
2. 대상 소재(사진·영상·데이터) 설명, 원하는 스토리
3. 원하는 연출 방식 — 잘 모르면 추천. 아래 참고표 사용:

   | 담당자에게 보여줄 이름 | 언제 적합한지 | `hk-interactive-template.md` 10장의 어떤 패턴 기반인지 |
   |---|---|---|
   | 스크롤로 계속 이어지는 여정형 | 등반/탐험/여정 서사 | 패턴 B (스크롤리텔링, 배경 고정 + IntersectionObserver) |
   | 예전/지금 비교 슬라이더 | 같은 장소·인물의 시간 변화 | 패턴 A(단순 롱폼) + React 아일랜드로 비교 슬라이더 컴포넌트 |
   | 시간순 타임라인 | 사건의 흐름을 순서대로 | 패턴 B 응용 (섹션을 시간순 배치) |
   | 지도 위 이동 경로형 | 이동 경로가 이야기의 핵심 | 패턴 C (React 아일랜드, `client:only="react"`) + 지도 라이브러리 자유 선택 |
   | 풀스크린 몰입 갤러리 | 사진 자체의 임팩트가 중요 | 패턴 A 또는 C |

   외부 라이브러리(GSAP, three.js, 지도 라이브러리 등)는 화이트리스트 없이
   자유롭게 선택 가능합니다. 다만 활발히 유지보수되는 라이브러리를 우선하고
   번들 크기에 신경 쓰세요.
4. 제목(`HTML_TITLE`), 요약 설명(`HTML_DESC`, 80자 이내 권장)
5. 폴더명(`FOLDER_NAME`, 영문 소문자+하이픈/언더스코어)
6. 연결 기사 키(`ARTICLE_KEY`, "A"+19자리) — **한국일보 기획팀이 발행**하는 값입니다.
   담당자가 직접 만들 수 없으니, 한국일보 담당자를 통해 발급받아 달라고 안내하세요.
   아직 못 받았다면 임시값으로 두고 넘어가되, `COMPLETION.md`에 "기사키 미발급
   — 배포 전 한국일보 확인 필요"라고 반드시 남기세요.
   이 값은 통계 메타뿐 아니라 **인터랙티브 임베드 스크립트의 `Nid=`**(헤더 +
   하단 추천 카드, 템플릿 0-1장)에도 들어갑니다. `Nid`는 대문자 N이고 값은
   `META.ts`의 `ARTICLE_KEY`를 그대로 씁니다 — 다른 곳에 하드코딩하지 마세요.
   임시값인 채 배포하면 추천 카드에 자기 기사가 뜨거나 카드가 안 뜹니다.
7. 게시 예정일(`POST_DATE`)
8. 제작진(`BYLINE_MEMBERS`) — 부서별로: 취재/사진/영상/인터랙티브 기획제작 등
9. 소재 파일(사진·영상·데이터) 첨부 + 각 소재의 출처(크레딧)와 사용 권한 확인
10. 디자인 컨셉, 톤&무드 — **페이지 색상을 라이트와 다크 중 무엇으로 할지** 꼭 확인하세요.
    담당자에게는 "페이지 색상을 라이트(흰 바탕)와 다크(검은 바탕) 중 어떤 걸로 할까요?"라고
    물으면 됩니다. 둘 중 하나로 고정하고, 페이지 안에서 바꾸는 전환 기능은 만들지 않습니다.
    이 답으로 `<html>`의 `dark` 클래스와 `_variables.sass`의 `$bgBase`가 정해집니다 (템플릿 0-1장 "테마").
    - 다크: `<html lang="ko" class="dark">`, `$bgBase`는 어두운 색 (템플릿 기본값)
    - 라이트: `<html lang="ko">` (클래스 없음), `$bgBase`는 밝은 색
11. 레퍼런스 사이트
12. 하지 말아야 할 것 (제약사항)

**콘텐츠 브리프 형식**: 사진·문구·배치를 담당자가 아래 형식으로 전달하면
왔다갔다하는 질문 없이 바로 `data.ts`에 옮길 수 있습니다. 담당자에게 이 형식을
안내하세요:

```
챕터 1: [제목]
- 본문: (문단1) / (문단2)
- 사진: [파일 경로 또는 링크] — 배치: 본문 사진 / 갤러리만 / 둘 다
- 크레딧: (출처·저작권 표기. 공통값과 다르면 명시)

챕터 2: ...
```

소재 파일은 `public/img/photos/`에 저장합니다. 링크로 받은 사진은
`curl -sL -A "Mozilla/5.0" -o <파일명> "<링크>"`로 받아 같은 폴더에 넣으세요.

메인 스토리 배경(연출 방식)과 어울리지 않는 사진·챕터(예: 산악 배경인데
국내 훈련 사진처럼 톤이 다른 소재)는 억지로 메인 스크롤에 끼워 넣지 말고,
갤러리 하단에 별도 그룹으로 분리하는 것도 좋은 패턴입니다 — 실제 사진이
아직 없으면 그룹 제목과 안내 문구만 먼저 넣고 "사진 준비 중"으로 표시하세요.

**공통 자산(로더 이미지)**: `assets/common/`에 실제 로더 이미지 2개
(`full_loader_bg.png`, `full_loader_spinner.png`)가 들어있습니다. 프로젝트
생성 시 그대로 복사하세요:

```bash
cp -r assets/common/. <프로젝트폴더>/public/img/common/
```

**폰트는 복사하지 않습니다.** 한국일보 CDN의
`https://assets.hankookilbo.com/fonts/hk_fonts.css`를 `Layout.astro` `<head>`에서
링크하는 방식이고, 템플릿 5장 Layout 원문에 이미 들어있습니다. 제공 서체는
`'Pretendard Variable'`(가변, 45~920)과 `'NanumMyeongjo'`(400/700/800) 두 가지이며
스타일에서는 `$fontBase` / `$fontSerif` 변수로 씁니다 (템플릿 7장). `public/fonts/`
폴더, 폰트 파일, `@font-face` 선언을 만들지 마세요 — `scripts/self_check.js`가
발견하면 실패 처리합니다. 다른 서체가 필요하면 한국일보 프론트개발팀에
`hk_fonts.css` 추가를 요청하세요.

답변을 모으면 프로젝트 루트에 `brief.md`를 작성하세요. **주의**: `brief.md`는
`META.ts`를 대체하지 않습니다 — 제목/URL/바이라인 같은 사이트 메타 정보는
`META.ts` 한 곳에만 씁니다. `brief.md`에는 그 문서에 없는 것(기획 배경, 연출 방식,
소재 출처)만 담습니다.

## 2단계 — 제작

**시작하기 전에 `references/hk-interactive-template.md` 전체를 읽으세요.**
이 문서의 0장~13장이 프로젝트 생성 방법 그 자체입니다. 문서의 "0. AI에게
이렇게 요청하세요"에 나온 형식대로, 1단계에서 모은 값(FOLDER_NAME, HTML_TITLE,
HTML_DESC, ARTICLE_KEY, POST_DATE, 바이라인)을 채워 프로젝트를 생성하고, 3번의
페이지 패턴(스크롤리텔링/단순 롱폼/데이터 시각화) 중 1단계에서 고른 연출
방식에 맞는 걸 고르세요.

**라이브러리 선택**: 캐러셀/슬라이더, 스크롤 인터랙션, 지도, 지도 위 데이터
시각화, React 아일랜드 간 상태 공유(퀴즈·계산기)가 필요하면
`hankookilbo-interactives-libs` 스킬의 규칙표를 먼저 확인하세요.
해당 없으면(예: 순수 스크롤형 사진 에세이) 참고할 필요 없습니다.

**소재 출처 표기**: 사진·영상마다 화면에 출처(크레딧)를 표기하세요. 사진 바로
아래 캡션에 넣는 것이 기본이고, 갤러리처럼 캡션 자리가 없으면 섹션 끝이나
바이라인 위에 출처 목록을 둡니다. 외부 링크는 모두 새 창/새 탭으로 엽니다
(`target="_blank" rel="noopener"`).

**방문자 데이터를 모아서 보여줘야 하는 기능(방명록, 참여 이벤트 등)을
요청받으면**: 이 템플릿은 정적 FTP 배포만 가능해 자체 백엔드를 둘 수
없습니다. 구글시트 + Apps Script를 "웹앱으로 배포"해 무료 백엔드처럼
쓰는 방법을 기본으로 제안하세요 (`doGet`/`doPost`로 시트 읽기/쓰기, POST는
`Content-Type: text/plain`으로 보내면 브라우저 preflight 없이 응답을 읽을
수 있음). 실제 시트 생성과 배포는 사용자의 구글 계정이 필요해 Claude가
대신 할 수 없으니, Apps Script 코드는 만들어 주고 배포 절차는 별도 문서
(`GUESTBOOK_SETUP.md` 같은 이름)로 안내하세요. 연동 전에는 `localStorage`
기반 데모 모드로 동작하게 해서, 실제 연동 전에도 바로 테스트해볼 수 있게
하는 것을 권장합니다.

## 3단계 — 1차 자체 QA (제작 직후)

```bash
npm run build
node scripts/self_check.js .
```

`self_check.js`는 공식 템플릿의 "빌드 후 자동 검증" grep 체크리스트 전체와
이 스킬의 고정 규칙(폰트는 CDN만, 로더 이미지, 용량 상한, `META.ts` 실제 값)을
함께 확인합니다. FAIL이 있으면 바로 고치세요.

추가로 시각적 확인:

```bash
npm install playwright --no-save   # 최초 1회
npx playwright install chromium    # 최초 1회
node scripts/qa_playwright.js --entry ./dist/index.html --out ./qa-report --sections "<챕터 선택자>"
```

`--sections`에는 이 페이지의 챕터(스크롤 단위) 요소 선택자를 넣습니다 (예: `".step"`, `".era-card"`,
`"main > section"`). 모바일(375×812)·PC(1440×900)에서 챕터마다 한 장씩 `mobile-01.png`,
`desktop-01.png` …로 찍고, 페이지 끝(바이라인) 화면 `*-end.png`와 `report.json`도 같은 폴더에 남깁니다.
기본은 챕터 가운데를 화면 가운데에 맞춰 찍습니다. 모바일에서 고정 그림이 화면 위쪽을 차지해
챕터 글이 가려져 찍히면 `--anchor-mobile 0.5`처럼 챕터 위쪽 끝이 놓일 화면 높이 비율(0~1)을
지정해 다시 찍으세요 (PC는 `--anchor-desktop`, 둘 다 같으면 `--anchor`).

`qa-report/`의 스크린샷을 직접 보고 레이아웃 문제를 먼저 스스로 고치세요. 콘솔 에러
중 `/Inc/Js/hkFunc.js`·`hkAnalTag_hub.js` 404는 로컬에서는 정상입니다 (한국일보 서버
전용 스크립트라 로컬에서 못 불러옴). 그 외 에러는 실제로 확인하세요.

`report.json`의 `fonts`·`embed` 항목으로 웹폰트, 인터랙티브 임베드(헤더·추천
카드)가 실제로 로드됐는지 확인하세요. 서체가
기본 서체로만 보이고 `assets.hankookilbo.com/fonts` 요청이 CORS 에러로 실패하면
코드 문제가 아니라 CDN 허용 목록 문제입니다 — 사용자에게 "한국일보 프론트개발팀에
CloudFront CORS 허용 목록(`localhost:3000`, `interactive.hankookilbo.com`) 확인
요청"이라고 안내하고 넘어가세요.

> **주의**: 이 템플릿은 `window`가 아니라 `.body-wrapper`가 실제 스크롤
> 컨테이너입니다. 콘텐츠 안에서 스크롤 관련 코드를 직접 짤 때
> `window.scrollY`, `window.addEventListener("scroll")`을 쓰면 동작하지
> 않습니다. `references/hk-interactive-template.md` 12장 "규칙과 함정"을
> 참고하세요.

### 담당자에게 스크린샷 확인 요청 (3단계의 마지막, 반드시 멈춘다)

스스로 고칠 것을 다 고쳤으면 `qa_playwright.js`를 한 번 더 돌려 `qa-report/`를 최신으로 만든 뒤,
**담당자에게 스크린샷 확인을 요청하고 답을 기다리세요.** 답을 받기 전에는 4단계로 넘어가지 않습니다.
화면이 기획대로 나왔는지는 담당자가 판단할 일이고, 이 확인이 끝나야 이후 단계(메타 확인, zip)가 의미가 있습니다.

요청 메시지에 담을 것 (담당자는 개발자가 아니므로 파일 경로와 볼 것을 구체적으로):
1. 폴더 위치: `<프로젝트폴더>/qa-report/` — Finder에서 열어 보면 된다고 안내
2. 파일과 챕터의 대응: `desktop-01.png` = 챕터 1 "(챕터 제목)", … 처럼 챕터 제목을 붙인 목록.
   목록이 5개를 넘으면 PC 전체 + "모바일도 같은 순서"로 줄인다
3. 봐 달라는 것 (3~5개): 사진·그림이 맞는 챕터에 들어갔는지, 글이 가려지거나 잘린 곳이 없는지,
   색·분위기가 기획과 맞는지, 모바일에서 글자가 읽히는지
4. 이미 Claude가 고친 것이 있으면 한 줄로 (예: "모바일에서 제목이 그림에 가려지던 것 수정함")
5. 답하는 방법: "괜찮다" 또는 "`desktop-03.png` 사진이 잘림"처럼 파일 이름으로 짚어 달라고 안내

피드백이 오면 고치고 → `npm run build` → `qa_playwright.js` 재실행 → 바뀐 파일만 다시 알려주며 재확인을 요청합니다.
담당자가 "괜찮다"고 하면 확인받은 날짜와 피드백 요약을 기억해 두었다가 6단계 `COMPLETION.md`에 적습니다.
`qa-screenshots/`처럼 다른 이름의 폴더를 따로 만들지 않습니다 — 스크린샷은 항상 `qa-report/` 한 곳입니다.

## 4단계 — 공통 요소 최종 확인

헤더(인터랙티브 헤더 웹컴포넌트)는 `<head>`의 임베드 스크립트가 자동으로 붙이고,
Byline(콘텐츠 크레딧)은 2단계에서 이미 `Layout.astro`에 포함되어 생성됩니다
(별도로 "붙이는" 단계가 아닙니다). 자체 헤더를 만들지 마세요. 화면 순서는
헤더 → 본문 → 바이라인입니다. 이 단계에서는 값이 실제로 채워졌는지만 확인하세요:

- `META.ts`의 모든 상수가 템플릿 기본값이 아닌 실제 값인지 (`self_check.js`가
  자동 확인)
- `BYLINE_MEMBERS`가 실제 제작진 정보로 채워졌는지
- 사진·영상마다 출처(크레딧)가 화면에 표기됐는지
- 로딩 화면(스피너)이 떠 있는 동안 헤더가 보이지 않는지. `_full_loader.sass`의
  `body.loading interactive-header` / `opacity: 0 !important` 규칙이 담당하며 `self_check.js`가
  있는지 확인합니다. 헤더를 건드리는 CSS는 이 한 줄이 유일한 예외입니다 (템플릿 0-1장 "헤더").
- `<html>`의 `dark` 클래스가 페이지 배경과 맞는지 (어두운 배경 = `class="dark"`). 어긋나면
  헤더 로고가 배경과 같은 색이 돼 안 보입니다. `self_check.js`가 `$bgBase` 밝기와 비교해 경고합니다.
- 공유 카드용 메타 4개(`og:title`, `og:description`, `og:image`, `kakao_og_image`)가
  실제 값이고 `ogimage.png`(1200×630)·`ogimage_kakao.png`(800×400)가 교체됐는지

## 5단계 — 2차 최종 QA

3단계와 동일하게 `self_check.js` + `qa_playwright.js`를 다시 실행하세요. 스크린샷은 같은
`qa-report/`에 덮어씁니다. 담당자가 확인한 뒤 화면이 바뀐 곳이 있으면 해당 파일을 알리고
다시 확인받으세요 (바뀐 곳이 없으면 재요청하지 않습니다).
추가로 `hk-interactive-template.md` "14. 배포 전 QA 체크리스트"를 하나씩
확인하세요 (인터랙티브 헤더 표시, 헤더 공유 버튼, 모바일 인앱 브라우저 스크롤 등).

## 6단계 — 완료 문서화

`brief.md` 옆에 `COMPLETION.md`를 새로 작성하세요. 브리프와 달리 이건
**최종적으로 실제 만들어진 상태의 기록**입니다. 포함할 내용:
- 최종 제목/URL(`THIS_URL`)/발행 예정일
- 최종 연출 방식 및 사용한 라이브러리
- 사용한 소재(사진·영상·데이터) 목록과 출처(크레딧)
- `self_check.js` 최종 실행 결과 (모두 통과했는지)
- 스크린샷 위치(`qa-report/`), 담당자 확인 날짜와 피드백 요약
- 한국일보 배포 담당자가 알아야 할 특이사항 (있다면. 예: 기사키 미발급, 외부 API 키)

## 7단계 — 폴더 정리

`node_modules/`, `.astro/`, 사용하지 않는 초안 파일을 삭제하세요.
**QA 스크린샷 원본(`qa-report/`)은 지우지 않습니다** — 담당자가 확인한 화면 기록이고 zip에 함께 들어갑니다.
최종 폴더에는 소스 전체(`src/`, `public/`, 설정 파일들)와 `dist/`, `qa-report/`,
`brief.md`, `COMPLETION.md`만 남아야 합니다. 배포 담당자가
`dist/`뿐 아니라 소스도 필요할 수 있으니 소스는 남겨두세요 (`node_modules`만
빼면 됩니다 — `npm install`로 다시 만들 수 있음).

## 8단계 — zip 패키징 및 전달 안내

```bash
zip -r <FOLDER_NAME>-final.zip <프로젝트폴더>
```

사용자에게 안내: "이 zip을 한국일보 담당자에게 전달하면 됩니다. 한국일보 배포팀은
`hk-interactive-template.md` 13장 절차대로 `dist/`를 FTP로
`interactive.hankookilbo.com/v/{FOLDER_NAME}/`에 업로드하고, 기사 CMS에 URL을
연결하고, 페이스북/카카오 OG 캐시를 갱신할 거예요."
